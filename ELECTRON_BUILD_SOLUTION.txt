ELECTRON BUILD SOLUTION - Native Module Compilation Fix
========================================================

PROBLEM:
- API server failed to start in production build
- Error: "NODE_MODULE_VERSION 136. This version of Node.js requires NODE_MODULE_VERSION 127"
- Native modules (better-sqlite3, node-pty, usearch, onnxruntime-node) compiled for wrong Node version

ROOT CAUSE:
- npm workspaces was hoisting dependencies to root node_modules
- Native modules were being compiled against system Node.js (v23) instead of Electron's Node.js (v22.17.1)

SOLUTION:

1. Install API dependencies locally without workspace hoisting:
   ```
   cd packages/api
   npm install --no-workspaces
   ```

2. Rebuild native modules for Electron's specific version:
   ```
   npx @electron/rebuild --force --electron-version 37.2.4 --arch arm64
   ```

3. Configure electron-builder.mjs to prevent interference:
   ```javascript
   npmRebuild: false,  // Disable electron-builder's rebuild
   asar: false,        // Allow API server to access node_modules
   files: [
     'packages/**/*',
     'packages/api/node_modules/**/*'  // Include API's local node_modules
   ]
   ```

4. Update build.sh script to handle dependencies correctly:
   ```bash
   # Install API dependencies locally
   cd packages/api
   rm -rf node_modules package-lock.json
   npm install --no-workspaces
   
   # Rebuild for Electron
   npx @electron/rebuild --force --electron-version 37.2.4 --arch arm64
   ```

RESULT:
- API server starts successfully in production
- All native modules work with Electron's Node.js runtime
- App packages and runs without MODULE_VERSION errors
