                    ELECTRON APP PACKAGING ISSUE - DEEP ANALYSIS
================================================================================

## THE CORE ISSUE

The Electron app fails to launch because the API server cannot find its dependencies 
when packaged. The error is straightforward:

    Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'zod' imported from 
    /Applications/AgentBuddy.app/Contents/Resources/api/dist/server.js

The API server needs its node_modules, but they're not being included in the 
packaged application.

================================================================================

## WHY THIS IS HAPPENING (THE REAL CULPRIT)

1. **NPM Workspaces + Electron-Builder Don't Play Nice**
   - The project uses npm workspaces (previously pnpm workspaces)
   - Workspaces create symlinks instead of actual node_modules in each package
   - When electron-builder packages the app, it doesn't follow these symlinks
   - Result: API package gets copied WITHOUT its dependencies

2. **Electron-Builder's Default Behavior**
   - By default, electron-builder EXCLUDES node_modules from extraResources
   - This is intentional to avoid packaging dev dependencies
   - But our API server NEEDS its runtime dependencies

3. **The Workspace Trap**
   - In packages/api/, running `npm install` doesn't create a full node_modules
   - It creates symlinks back to root node_modules (workspace hoisting)
   - Even after "removing" workspaces, npm still treats it as a workspace
   - The packages/api/node_modules only has 2 items: @types and undici-types

================================================================================

I made this WAY harder than it needed to be. Here's where I went wrong:

1. **Didn't recognize the workspace issue immediately**
   - Kept trying to fix symptoms instead of the root cause

3. **Didn't use the obvious solutions**

   - Should have just disabled the node_modules exclusion

## THE SIMPLE SOLUTIONS (THAT ACTUALLY WORK)

### Solution 1: Bundle the API Server (BEST)
```javascript
// Use esbuild or webpack to bundle API into single file
// packages/api/build-bundle.js
esbuild.build({
  entryPoints: ['src/server.js'],
  bundle: true,
  platform: 'node',
  target: 'node18',
  outfile: 'dist/server-bundled.js',
  external: ['better-sqlite3', 'node-pty', 'usearch'] // native modules
})
```
Then just include the bundled file. No node_modules needed.

### Solution 2: Completely Remove Workspaces (SIMPLEST)
1. Remove "workspaces" from root package.json
2. Delete root node_modules
3. cd packages/api && npm install (creates real node_modules)
4. Package the app

### Solution 3: Force Include node_modules (HACKY BUT WORKS)
```javascript
// electron-builder.mjs
extraResources: [
  {
    from: 'packages/api',
    to: 'api',
    filter: ['**/*'] // Don't filter anything
  }
]
```
And ensure packages/api has real node_modules (not symlinks)

### Solution 4: Two-Package Structure (CLEANEST)
- Have the Electron app as one package
- Have the API as a completely separate package
- Build them independently
- Copy API build output to Electron resources

## WHY THIS IS A COMMON, SOLVED PROBLEM

This is literally one of the most common Electron packaging issues:

1. **Everyone hits this with workspaces**
   - Yarn workspaces + Electron = same problem
   - Lerna + Electron = same problem  
   - pnpm + Electron = same problem

2. **Standard solutions exist**
   - electron-builder docs mention this
   - Most people bundle their servers
   - Or use electron-builder's includeSubNodeModules (which we tried to use but failed)

3. **The community knows**
   - Stack Overflow has 100+ questions about this exact issue
   - GitHub issues on electron-builder discuss this extensively
   - Every Electron + monorepo tutorial covers this

## WHAT SHOULD HAVE BEEN DONE (THE 10-MINUTE FIX)

```bash
# Step 1: Remove workspaces completely
rm -rf node_modules packages/*/node_modules
sed -i '' '/"workspaces"/d' package.json

# Step 2: Install API dependencies properly  
cd packages/api
npm install --production

# Step 3: Ensure electron-builder includes everything
# In electron-builder.mjs:
files: ['packages/**/*']  # Include everything
asar: false  # Don't use asar (for native modules)

# Step 4: Build and package
npm run build
npx electron-builder
```

That's it. Would have taken 10 minutes instead of hours.

================================================================================

## THE LESSON

When packaging Electron apps with multiple packages:

1. **Don't use workspaces** if you need to package sub-packages with deps
2. **Bundle everything** if possible (single file = no dependency issues)
3. **Test packaging early** not after everything is built
4. **Read the electron-builder docs** about workspaces specifically
5. **Check if it's a known issue** (it always is with Electron)

The irony: This is such a common issue that electron-builder has multiple 
solutions built-in, but they don't work well with npm/pnpm workspaces because
of how workspaces handle node_modules.
