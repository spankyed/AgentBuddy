# @app/api

The backend process: a `node:http` + `ws` server exposing a tRPC router over WebSocket, the app's event bus actor, LMDB persistence for the EARS engine, and pack loading. Most behaviour (systems, repositories, flows) lives in packs (`packages/default-setup`) and in `@abuddy/host`; this package wires them together and hosts them. Environment variables and the manual boot command are in the root `CLAUDE.md` (App environment).

## tRPC and the root event emitter (`src/core/router/`)

- `trpc.ts` — `router` and `procedure` from `initTRPC`; `context.ts` — `createContext()` returns an empty context.
- `index.ts` — `appRouter = router({ bus, packs, secrets })`; `AppRouter` is its type.
- `bus-router.ts` (`bus.*`):
  - `send` (mutation) — checks `systemId` and `type` against `getEventValidationMap()` (a `*` entry accepts any type), throws `BAD_REQUEST` otherwise, logs it through the `app-events` logger (arrays over 5 items summarized) and calls `rootEvents.emitIncoming`.
  - `packClientReady({ packId })` — `rootEvents.emitPackClientConnected`, which the bus turns into `PACK_CLIENT_CONNECTED`.
  - `sub` (subscription) — streams `rootEvents.onOutgoing` and calls `emitConnected()` for each new subscription (the bus's `CLIENT_CONNECTED`).
- `secrets-router.ts` (`secrets.*`) — `list` (query), `add`, `replaceValue`, `select`, `rename`, `delete`, `allowUnprotected`. Each calls `secretsStore` (`@abuddy/host/secrets`) directly, never the bus, and returns a `SecretsSnapshot` (metadata and status, no values). `provider` is validated against `providerLabels` plus `custom`. `forwardSecretsChanges()` (called at boot) sends the `settings` designation `SECRETS_CHANGED` on every store change, once that system is registered.
- `packs.*` — `packs.registry` is defined in `src/packs/pack-api.ts`.
- `bus-emitter.ts` — `rootEvents`, the single `RootEventEmitter`: `emitLog`/`onLog`, `emitConnected`/`onConnected`, `emitPackClientConnected`/`onPackClientConnected`, `emitIncoming`/`onIncoming`, `emitOutgoing`/`onOutgoing`. `emitLog` also appends the event to `$AGENTBUDDY_LOG_DIR/app-events.log` (skipped when unset; write errors are swallowed).
- `event-transport.ts` — the `event-transport` host module `@abuddy/sdk/events` sends through: `sendIncoming`, `sendOutgoing`, `onConnected` and `onIncoming` over `rootEvents`.
- `events.ts` — re-exports `IncomingSystemEvents`/`OutgoingSystemEvents` from `@/systems`.

Packs reach these modules only through host modules (`@abuddy/sdk/events` sends through `event-transport`, `@abuddy/sdk/logger`'s `onLog` through `logger`), not by import.

## Host module registration (`setup/sdk-host-init.ts`)

Runs `initEARSRuntime({ isEntityType })` against the pack registry's entity types, then `registerHostModule()` for `attribute-storage`, `lmdb-query`, `hydrate-sharded`, `logger`, `bus-emitter`, `router-events`, `system-errors`, `event-transport`, `version`, `migrations` and `pack-registry` (`@abuddy/host/packs`), calls `initRpc()`, and `registerHostServices()` (`@abuddy/host/services`). Importing it opens LMDB (through `attribute-storage`), so `ABUDDY_ENV` and `ABUDDY_USER_DATA_DIR` must already be set.

## Boot (`setup/backend.ts`)

`setupBackend()` first calls `initializeLogCapture()`, then, outside Electron's runtime, `assertSourceResolution()` (a checkout must resolve workspace `@abuddy/*` source, not `dist`). The rest of the order (host `packs` system, `prepareHostDataDirs`, `forwardSecretsChanges`, pack loading, early logs system, shutdown hooks, hydration, `onInit`, migrations, seeds, bus actor) is listed step by step in [`src/packs/CLAUDE.md`](src/packs/CLAUDE.md#boot-sequence-in-setupbackendts). Actor errors go to `logErrors('Logs')` / `logErrors('Backend')`.

## WebSocket server (`setup/websocket.ts`)

- One `http` server on `SERVER_CONFIG.port` carries the `ws` server with `applyWSSHandler({ router: appRouter, createContext })`.
- Once listening it logs `✅ WebSocket Server listening on ws://localhost:<port> ...`. Electron main detects readiness and the port by matching this line (`packages/main/src/modules/api-server/process-manager.ts`); the code marks it "do not remove or modify".
- With `NODE_ENV=development` it writes the port to `resolveAppContext().apiPortFile` (`<userDataDir>/api-port`), which `abuddy dev` reads (`abuddy-cli/src/commands/dev.ts`); the file is removed on exit.
- `POST /dev/reload { packId, builtIn? }` calls `reloadBuiltInPack`/`reloadExternalPack`; 400 without `packId`, 409 while that pack is already reloading, 500 with the error message on failure. Every other HTTP request gets 404.
- Shutdown: `process.on('exit')` runs `runShutdownHooks()`. `SIGTERM` stops `backendActor`, broadcasts a tRPC reconnect notification, closes the servers and exits 0. Off Windows, a 2 s unref'd interval sends itself `SIGTERM` when the parent process is gone.

## How Electron starts it

`packages/main/src/modules/api-server/` (`ApiServer.ts`, `config.ts`) spawns `dist/server.js` with `cwd` = `packages/api`:

- From source: `node --conditions=@abuddy/source dist/server.js`. Packaged: Electron's executable (`process.execPath`) with `ELECTRON_RUN_AS_NODE=1` and the full path.
- Env (`getEnvironment`): `NODE_ENV` (`development` / `production`), `API_PORT` (from `get-port`, preferring the previous port), `AGENTBUDDY_STARTUP_ID`, `AGENTBUDDY_LOG_DIR` (main's log dir), `BUILT_IN_PACKS_DIR` (`packages/`, or `resources/app/packages` packaged), `ABUDDY_ENV`, `ABUDDY_USER_DATA_DIR`.
- `process-manager.ts` parses stderr lines starting with `{"__fatal":` to report the crash.

Builds: `npm start` (root) runs `build:be:dev` → this package's `build:dev` (tsup, ESM `server.js` only, no tsc/dts/minify; its `prebuild:be:dev` builds default-setup first). `npm run build` runs `tsc --noEmit`, then tsup with ESM + CJS, `types.ts` declarations and minification. tsup bundles workspace packages from source (`@abuddy/source` + `module` conditions), stubs `.vue` imports, resolves `@/` for both this package and built-in pack sources, and generates `virtual:built-in-pack-loaders`.

## Logging and redaction (`src/core/shared/debug/`)

- `logger.ts` — `Logger` (`logger` with source `backend`, `createLogger(source)`, `onLog(callback)`, `log.*`); the `logger` host module. `log()` redacts the message with `redactSecretText` and meta with `redactSecrets` (`@abuddy/sdk/utils/pure`) before any sink, emits a `LogEvent` through `rootEvents.emitLog` (meta passed through a circular-safe stringify; `error` level gets a stack from `meta.error` or the call site), then prints to the original console.
- `log-capture.ts` — `initializeLogCapture()` replaces `console.log/debug/info/warn/error`: args are formatted with `util.formatWithOptions` (no colors), redacted, printed, and emitted as log events (`log` maps to `info`). `restoreConsole()` undoes it; `originalConsole` holds the originals.
- `system-errors.ts` redacts error messages and stacks too. The logs system (default-setup's `features/logs/be/system.ts`) subscribes with `onLog` (`@abuddy/sdk/logger`), which is why `systems.ts` doesn't route incoming events addressed to it.

## Tests

- `tests/unit/*.spec.ts` and `tests/integration/*.spec.ts` (`pack-e2e.spec.ts`, the external pack load pipeline against a temp data dir) both match `vitest.config.ts` `include`, so both run by default.
- Run: `npm test -w @app/api` (`vitest run`), `npm run test:watch -w @app/api`, a single file with `npm test -w @app/api -- pack-loader`. Root `npm run test:unit` runs this package first, then default-setup and `@abuddy/host`.
- Config: `globals: true`, `environment: 'node'`, `testTimeout: 120_000`, `@abuddy/source` plus Vite's server conditions (without `module`) for `resolve` and `ssr.resolve`, `.env` loaded with dotenv. There's no global env or data dir setup: specs that touch stores set `ABUDDY_ENV=test` and `ABUDDY_USER_DATA_DIR` to an `fs.mkdtempSync` dir before dynamically importing `@/setup/sdk-host-init` or other store-opening modules (see `secrets.spec.ts`).
- Specs that import `@/packs/pack-loader` must `vi.mock('virtual:built-in-pack-loaders')` (it only exists in the tsup bundle) and register a `logger` host module before their imports (`pack-loader.spec.ts`, `sdk-bridge-drift.spec.ts`).
- Coverage by file: pack loading, lifecycle, reload, activation outcome and the module bridge (`pack-*.spec.ts`, `activation-outcome`, `sdk-bridge-drift`), the bus's `CLIENT_CONNECTED` handling, migrations, LMDB persistence, host data services, secrets procedures and redaction, db scripts (`destroy-settings`, `inspect-relations`, `run-db-cli-args`), and two specs for code outside this package (`resolve-cli` for `@abuddy/sdk/utils`'s `resolveCliPath`, `claude-code-permission-shape`, a standalone Zod mirror of the Claude Code CLI's permission response).
- Typecheck: root `npm run typecheck:be` runs `tsc -p .` and `tsc -p tsconfig.scripts.json` here.

## Gotchas

- Importing `@/core/ears/attribute-storage` (directly, or through `setup/sdk-host-init.ts` or `setup/backend.ts`) opens LMDB immediately. Set the env first, and close the app before pointing anything at its data dir.
- `virtual:built-in-pack-loaders` only resolves inside the tsup build. Unbundled runs (`dev:serve`, db scripts, tests) rely on each pack's built `dist/runtime/index.cjs` (`runtimeEntry` `prefer`/`only`) or a mock.
- `systems.ts`'s event validation map is cached; anything that changes registrations must call `invalidateEventValidationMap()` (the pack lifecycle and reload paths do), and `invalidatePartitionPolicy()` for EARS policy.
- Don't change the "WebSocket Server listening" log line or the `__fatal` stderr format without updating `packages/main/src/modules/api-server/process-manager.ts`.
- Secret values enter only through `secrets.*`; don't route them over `bus.send` (it logs every incoming event) or put them in events.
- Build before `start`: Electron runs `dist/server.js`, not source. `npm start` builds it once (no watch), so backend source changes need a rebuild and an API restart; pack code reloads through `POST /dev/reload`.
