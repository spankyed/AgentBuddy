# @app/api

The backend process: a `node:http` + `ws` server exposing a tRPC router over WebSocket and the root event bus, the process boot, and the composition that opens the app's LMDB store (`@abuddy/ears/lmdb`) for the EARS engine and binds the app. It holds nothing else: behaviour (systems, repositories, flows) lives in packs (`packages/default-setup`), and app runtime in `@abuddy/host`, including the pack runtime (`@abuddy/host/packs/runtime`: loading, lifecycle, reload, seeding), the app bus (`createAppBus(registry)`, `@abuddy/host/bus`), the migrations runners (`@abuddy/host/migrations`) and the host services (`createHostRuntime()`, `@abuddy/host/services`); this package wires them together and serves them. `tests/unit/source-layout.spec.ts` lists the files `src/` may hold. Environment variables and the manual boot command are in the root `CLAUDE.md` (App environment).

## Layout

`src/` is one folder per job this package does, and `packages/renderer/src` is the same four plus `views/`, so a
concept found in one is looked for in the same place in the other (`tests/unit/source-layout.spec.ts` says so on
both sides):

| Folder | What belongs there | The renderer's counterpart |
|---|---|---|
| `boot/` | what runs before the app exists: fatal-error handling, the process's config | `boot/` |
| `runtime/` | this process's resources (the store, the engine, the registry) and binding the app | `runtime/` |
| `transport/` | the wire to the renderer: the tRPC routers, the root event emitter, the ws server | `transport/` (the client) |
| `adapters/` | this process's implementations of what host code is given — today the console | `adapters/` |

`server.ts`, `types.ts` and `env.d.ts` sit at the root. There is no `core/`, `shared/`, `lib/` or `utils/`: a folder
named for a layer rather than a job takes whatever nobody placed, and the guard rejects one. Anything that isn't
transport, boot or composition belongs in `@abuddy/host`, which the same guard is there to keep true.

## Source map (`src/`)

| Path | Purpose |
|------|---------|
| `server.ts` | Entry. Loads `dotenv`, calls `installFatalErrorHandling()` (`boot/errors.ts`), then runs `setupBackend()` and `createWebSocketServer()`. Any failure is written to stderr as a `{"__fatal": true, message, stack, source}` JSON line and the process exits 1 |
| `types.ts` | The `types` entry (`dist/types.d.ts`): `AppRouter`, `EARS`, `BaseEntity`, pack seed preview types |
| `env.d.ts` | Declares `virtual:built-in-pack-loaders` (generated by `tsup.config.ts`, resolved from `src/runtime`), which `runtime/index.ts` passes to `loadBuiltInPacks` as `bundledLoaders` |
| `transport/` | tRPC, the root event emitter and the ws server (below) |
| `adapters/logging.ts` | Log output (below) |
| `runtime/index.ts` | The composition: `openAppStore()`, which creates the app's registered packs, opens the store and binds the app (below), `setupBackend()`, the exported `appPacks` (the app's registry, which `transport/bus.ts` and `transport/websocket.ts` work on) and `backendActor` (`createAppBus(appPacks)`, with systemId `bus` from `@abuddy/host/bus`), and `logErrors(actor)` (an actor error observer that reports a fatal system error with `reportError` and writes a `__fatal` line). The app version is the root `package.json`'s |
| `transport/websocket.ts` | `createWebSocketServer()` (below) |
| `boot/config.ts` | `SERVER_CONFIG.port` (`API_PORT`, default 3001), `WS_CONFIG` (accepts every connection) |

## tRPC and the root event emitter (`src/transport/`)

- `trpc.ts` — `router` and `procedure` from `initTRPC`; `context.ts` — `createContext()` returns an empty context.
- `index.ts` — `appRouter = router({ bus, packs, secrets })`; `AppRouter` is its type.
- `packs.ts` (`packs.*`) — `registry` (query): `LoadedPackEntry[]` (typed from `@abuddy/host/packs`, so `AppRouter`'s declarations don't pull the pack runtime into the renderer's typecheck) from `getLoadedPackEntries()` (`@abuddy/host/packs/runtime`), the packs the renderer loads frontends from.
- `bus.ts` (`bus.*`):
  - `send` (mutation) — `receiveClientEvent(appPacks, event)` (`@abuddy/host/bus`), which checks `systemId` and `type` against the app's registered systems (a `*` entry accepts any type), logs the event through the `app-events` logger (arrays over 5 items summarized) and emits it on the bound root event bus. Its `UnknownClientEventError` becomes `BAD_REQUEST`.
  - `packClientReady({ packId })` — logs it and calls `rootEvents.emitPackClientConnected`, which the bus turns into `PACK_CLIENT_CONNECTED`.
  - `sub` (subscription) — streams `rootEvents.onOutgoing` and calls `emitConnected()` for each new subscription (the bus's `CLIENT_CONNECTED`).
- `secrets.ts` (`secrets.*`) — `list` (query), `add`, `replaceValue`, `select`, `rename`, `delete`, `allowUnprotected`. Each calls `secretsStore` (`@abuddy/host/secrets`) directly, never the bus, and returns `secretsSnapshot()` (metadata and status, no values). `provider` is validated against `providerLabels` plus `custom`. The boot calls host's `forwardSecretsChanges()`, which sends the `settings` designation `SECRETS_CHANGED` on every store change, once that system is registered.
- `emitter.ts` — `rootEvents`, the single `RootEventEmitter` (it implements the SDK's `RootEvents`, and is the `transport` the app binds): `emitLog`/`onLog`, `emitConnected`/`onConnected`, `emitPackClientConnected`/`onPackClientConnected`, `emitIncoming`/`onIncoming`, `emitPluginSend`/`onPluginSend` (sends to plugins from outside a system, which `createAppBus()` routes through the bus actor), `emitOutgoing`/`onOutgoing` (what the clients receive). `emitLog` also appends the event to `$AGENTBUDDY_LOG_DIR/app-events.log` (skipped when unset; write errors are swallowed).

Packs reach these modules only through the bound `HostRuntime` (`@abuddy/sdk/events` and `@abuddy/sdk/logger` send, log and report errors over `transport.rootEvents`), not by import.

## Binding the app and the store (`openAppStore()` in `runtime/index.ts`)

Importing `runtime/index.ts` opens and binds nothing. `openAppStore()` creates the app's registered packs (`createPackRegistry()` from `@abuddy/host/packs`, exported as `appPacks`; every later boot step registers into it) and opens the app's data with `openDatabaseStore({ paths, schema: packs })` (`@abuddy/host/database`, the composition `abuddy db` opens a data dir with too): the LMDB store at `_getLmdbPath()`/`_getVolatileLmdbPath()` with the registry's `partitionPolicy`, and the app's engine persisting to it and checking the registry's entity types, then `bindHost(createHostRuntime({ store, engine, transport: { rootEvents }, appVersion: APP_VERSION, packs }))` (`@abuddy/host/services`, the only place the runtime is assembled; `APP_VERSION` is the root `package.json`'s version), and `printLogEvents()`. `bindHost` runs once per process: a spec that opens the store twice calls `unbindHost()` (`@abuddy/sdk/runtime/internals`) in between (`restart-persistence.spec.ts`). `bindHost` installs the engine's query face for `@abuddy/ears`'s free functions; the composition keeps the `admin` face (host services); the SDK's registries of what packs registered read the bound registry. It returns `{ store, engine, packs }`; the caller hydrates the store (`store.hydrate()`) once the packs are registered. `setupBackend()` calls it first, and so do the one-off `scripts/db/fix-prod-upgrade.ts` (through `scripts/db/database.ts`) and the specs that touch stores. `ABUDDY_ENV` and `ABUDDY_USER_DATA_DIR` must be set before the call. This package keeps `lmdb` as a dependency so the packaged app ships it (tsup leaves it external), but no code here imports `lmdb` (`check:specifiers`).

## Boot (`runtime/index.ts`)

`setupBackend()` first calls `initializeLogCapture()` and `openAppStore()`, then, outside Electron's runtime, `assertSourceResolution()` (a checkout must resolve workspace `@abuddy/*` source, not `dist`). The rest of the order (host `packs` system, `prepareHostDataDirs`, `forwardSecretsChanges` (`@abuddy/host/secrets`), pack loading, early logs system, shutdown hooks, hydration, `onInit`, migrations (`runAppMigrations`/`runPackMigrations` from `@abuddy/host/migrations`), seeds, bus actor) is listed step by step in [the pack runtime's CLAUDE.md](../abuddy-host/src/packs/runtime/CLAUDE.md#boot-sequence-in-the-apis-setupbackendts). Actor errors go to `logErrors('Logs')` / `logErrors('Backend')`.

## WebSocket server (`transport/websocket.ts`)

- One `http` server on `SERVER_CONFIG.port` carries the `ws` server with `applyWSSHandler({ router: appRouter, createContext })`. It listens on loopback only (`API_HOST` from `@abuddy/sdk/utils/pure`, `127.0.0.1`): nothing on the network reaches it. Every client takes the address from there too (the renderer's tRPC client, `abuddy dev`, default-setup's `dev-build.mjs`, the E2E tests).
- Every client needs the API token (`apiToken()` in `boot/config.ts`: `ABUDDY_API_TOKEN`, which Electron main creates per app run, or, for an API started by hand without it, a random one the API makes up and keeps; `apiTokenIsOwn()`). A WebSocket connection offers it as a subprotocol, `abuddy-token.<token>` next to `abuddy` (`acceptsConnection` reads `Sec-WebSocket-Protocol`; the server answers `abuddy`, `API_PROTOCOL`, never echoing the token). It stays out of the URL, which browsers print when a connection fails and the app logs, and the check parses no URL, so a malformed request can't throw; the HTTP endpoints take it in `API_TOKEN_HEADER` (`@abuddy/sdk/utils/pure`). Tokens compare in constant time (`isApiToken`). A web page, the in-app browser's included, can't learn it, so it can't call the API (`tests/unit/dev-reload-access.spec.ts`, `tests/e2e/api-access.spec.ts`).
- Once listening it logs `✅ WebSocket Server listening on ws://localhost:<port> ...`. Electron main detects readiness and the port by matching this line (`packages/main/src/modules/api-server/process-manager.ts`); the code marks it "do not remove or modify".
- Every run writes its port and process id to `resolveAppContext().apiPortFile` (`<userDataDir>/api-port`, `{ port, pid }`), so a local tool finds this API and can tell an app is running on the data dir, and tells a file a crashed run left behind from a live one (`readApiEndpoint` in `@abuddy/sdk/env`, which `findRunningApp` and `abuddy dev` read; the port alone opens nothing, since every call needs the token). The token goes to `apiTokenFile` (`api-token`) only where a local tool may use it: `NODE_ENV=development` (`abuddy dev` and default-setup's `dev-build.mjs` read both files), or an API that made up its own token, which also logs where it is (`abuddy-cli/src/commands/dev.ts`). `publishApiFiles` writes both through a new file created with mode `0600` and renamed into place, so only the user reads them whatever the data dir allows and an existing file's permissions never carry over. Both are removed on exit.
- `setupBackend()` refuses to boot while a tool holds the data dir's database write lock (`assertNoDatabaseWriter`, `@abuddy/host/database`): `abuddy db` holds it while it changes the database, so the app never starts on data that is about to change under it (`tests/unit/db-write-lock.spec.ts`).
- `POST /dev/reload { packId, builtIn? }` calls `reloadBuiltInPack`/`reloadExternalPack` (`@abuddy/host/packs/runtime`). `devReloadRefusal` answers 403 unless the app is a development or test build and the request carries the API token; 400 without `packId`, 409 while that pack is already reloading, 500 with the error message on failure. Every other HTTP request gets 404.
- Shutdown: `process.on('exit')` runs `appPacks.runShutdownHooks()`. `POST /dev/reload` reloads a pack in `appPacks`. `SIGTERM` stops `backendActor`, broadcasts a tRPC reconnect notification, closes the servers and exits 0. Off Windows, a 2 s unref'd interval sends itself `SIGTERM` when the parent process is gone.

## How Electron starts it

`packages/main/src/modules/api-server/` (`ApiServer.ts`, `config.ts`) spawns `dist/server.js` with `cwd` = `packages/api`:

- From source: `node --conditions=@abuddy/source dist/server.js`. Packaged: Electron's executable (`process.execPath`) with `ELECTRON_RUN_AS_NODE=1` and the full path.
- Env (`getEnvironment`): `NODE_ENV` (`development` / `production`), `API_PORT` (from `get-port`, preferring the previous port), `AGENTBUDDY_STARTUP_ID`, `AGENTBUDDY_LOG_DIR` (main's log dir), `BUILT_IN_PACKS_DIR` (`packages/`, or `resources/app/packages` packaged), `ABUDDY_ENV`, `ABUDDY_USER_DATA_DIR`.
- `process-manager.ts` parses stderr lines starting with `{"__fatal":` to report the crash.

Builds: `npm start` (root) runs `build:be:dev` → this package's `build:dev` (tsup, ESM `server.js` only, no tsc/dts/minify; its `prebuild:be:dev` builds default-setup first). `npm run build` runs `tsc --noEmit`, then tsup with ESM + CJS, `types.ts` declarations and minification. tsup bundles workspace packages from source (`@abuddy/source` + `module` conditions), stubs `.vue` imports, resolves `@/` for both this package and built-in pack sources, and generates `virtual:built-in-pack-loaders`.

## Logging and redaction (`src/adapters/logging.ts`)

Loggers and error reports are SDK code (`@abuddy/sdk/logger`): a bound `createLogger` redacts its entry and emits it as a log event on `rootEvents` (meta through a circular-safe copy, an `error` entry with a stack from `meta.error` or the call site); `reportError` without `step` emits a log event and a `SYSTEM_ERROR` to the `application` plugin (redacted, with a user-safe message for `RepositoryError` NOT_FOUND). This file is the API's output of them:

- `printLogEvents()` prints every log event on `rootEvents` to the original console once (`[source] message meta`; `info` through `console.log`). `openAppStore()` starts it, so the db scripts print what they log too.
- `initializeLogCapture()` also replaces `console.log/debug/info/warn/error`: args are formatted with `util.formatWithOptions` (no colors), redacted and emitted as log events (`log` maps to `info`), which the printer prints. Nothing is printed twice (`log-capture.spec.ts`). `restoreConsole()` undoes the replacement; `originalConsole` holds the originals.
- The logs system (default-setup's `features/logs/be/system.ts`) subscribes with `onLog` (`@abuddy/sdk/logger`), which is why the app bus (`createAppBus(registry)`) doesn't route incoming events addressed to it.

## Gotchas

- `openAppStore()` (called by `setupBackend()`, and on import of `scripts/db/database.ts`) opens LMDB and binds the app (once per process). Set the env first, and close the app before pointing anything at its data dir. An engine created without `store.sink` writes nowhere (`restart-persistence.spec.ts`).
- LMDB's adapter, sharded router, query layer and store specs live in `@abuddy/ears` (`tests/lmdb/`).
- `virtual:built-in-pack-loaders` only resolves inside the tsup build. Unbundled runs (`dev:serve`, `scripts/db`, tests) rely on each pack's built `dist/runtime/index.cjs` (`runtimeEntry` `prefer`/`only`) or pass their own `bundledLoaders`.
- Pack runtime specs (loading, lifecycle, reload, the bridge), the migrations runners' and `receiveClientEvent`'s live in `@abuddy/host` (`tests/packs/runtime/`, `tests/migrations/`, `tests/bus/`), not here.
- New code that isn't transport, boot or composition goes in `@abuddy/host`; `source-layout.spec.ts` fails on any other file under `src/`.
- Don't change the "WebSocket Server listening" log line or the `__fatal` stderr format without updating `packages/main/src/modules/api-server/process-manager.ts`.
- Secret values enter only through `secrets.*`; don't route them over `bus.send` (it logs every incoming event) or put them in events.
- Build before `start`: Electron runs `dist/server.js`, not source. `npm start` builds it once (no watch), so backend source changes need a rebuild and an API restart; pack code reloads through `POST /dev/reload`.
